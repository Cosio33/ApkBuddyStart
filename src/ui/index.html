Instalar Android en el disco virtual

La ventana de la máquina virtual está abierta. Sigue estos 6 pasos una vez; después ApkBuddyStart arrancará directamente desde el disco y no necesitará la imagen.

  1. Menú de inicio： usa↓seleccionaInstallation - Install Android-x86 to harddisk，Enter
  2. Choose Partition： eligeCreate/Modify partitions；cuando pregunte si usar GPT, eligeNo
  3. Particionado cfdisk：New → Primary→ Capacidad: pulsa Enter →Bootable → Write→ Introduceyes → Quit
  4. Formatear： eligevda1→ Cuando pida formatear, eligeext4 → Yes
  5. Arranque y sistema：Install GRUBEligeYes；Install /system as read-writeEligeYes
  6. Completado：cuando la barra llegue al 100 %, pulsa «Ya terminé la instalación» (ApkBuddyStart se reiniciará y tomará el control automáticamente)

Si después aparece «adb no conectado», pulsaCtrl+Alt+F1Entra en el terminal y ejecutasetprop service.adb.tcp.port 5555、stop adbd、start adbd， pulsaCtrl+Alt+F7volver a la interfaz gráfica.

Botones del ratón
El emulador trata el clic izquierdo como un toque; mantener y arrastrar es un desplazamiento, sin configuración adicional.
El emulador trata el clic derecho como otro clic (fácil de pulsar por error). Al activarlo, el clic derecho solo hará «Atrás» y no disparará un clic.
El modo suave agrupa varias ruedas del ratón en un único gesto de desplazamiento, evitando movimientos a saltos y lanzando un proceso adb por cada paso.
La asignación de botones laterales requiere un gancho global del ratón. Solo se instala mientras la ventana de ApkBuddyStart está en primer plano y se retira al perder el foco o al cerrarse, sin ralentizar el escritorio.
Estas asignaciones solo se aplican cuando la ventana de la aplicación está en primer plano; al volver al escritorio o cerrar la ventana, el ratón se comporta con normalidad en Windows.
Mapeo de teclado (mando de juego)
Asigna teclas del teclado a toques/desplazamientos táctiles de Android. Útil para jugar en el PC (WASD para moverte, J/K para habilidades, etc.). Cada aplicación se configura por separado: clic derecho en su tarjeta → «Mapeo de teclado» para elegir una plantilla o personalizarla.
Esta aplicación no tiene un mapeo de teclado configurado. Haz clic derecho en su tarjeta para aplicar una plantilla rápidamente.
Rendimiento y consumo de recursos
Decide cuánta CPU consume la máquina Android y la nitidez de la imagen. Si Douyin o Douyin Lite van lentos, elige «Fluido»; si solo quieres dejar aplicaciones pequeñas abiertas, elige «Ahorro de recursos». El cambio se aplica la próxima vez que abras la aplicación.
La ampliación se hace in situ: se conservan las aplicaciones y los datos; solo se tarda algo más en abrir la aplicación la próxima vez.

Detalles del contenedor (avanzado)
Limita la cuota de vCPU y baja la prioridad del proceso; la CPU se cede al escritorio de Windows. La «política de recursos» de arriba ya lo configura automáticamente.
El modo juego mantiene la máquina Android con prioridad CPU alta y reduce el sondeo en el host; la entrada y la imagen tienen la latencia mínima. El coste es que los demás programas van más lentos. Sin ventanas de aplicación, el contenedor baja de prioridad automáticamente.
Desactiva además los paquetes en segundo plano Play Store, asistente de configuración, servicio de impresión, etc., y deja solo lo necesario para abrir aplicaciones. Si una aplicación avisa de que falta Google Play Services, desactiva este interruptor para restaurarlos automáticamente.
Al iniciar ApkBuddyStart, prepara el entorno Android en segundo plano (ventana oculta todo el tiempo; no verás el emulador). Después, abrir cualquier aplicación solo requiere un «Abrir»: de más de 20 segundos pasa a ser casi instantáneo. El coste es unos 1 GB de RAM en reposo; si lo desactivas, la primera apertura será en frío.
El entorno Android arranca una sola vez y se mantiene activo; abrir una aplicación no vuelve a iniciar todo el sistema, solo lanza esa aplicación y detiene los demás procesos. Cerrar la última ventana limpia el segundo plano y aparca el contenedor, así que volver a abrir es casi instantáneo.
Descarga y fuentes de actualización
«Automático» consulta las últimas versiones en GitHub y Gitee, descarga 256 KB de cada enlace para medir la velocidad y elige el más rápido; si una fuente falla, la otra sigue funcionando.
Cuando GitHub es demasiado lento, prueba también estos servicios públicos de aceleración ghfast.top / gh-proxy.com (solo reenvían archivos públicos, sin acceso a cuentas). Desactivarlos deja solo la conexión directa y los prefijos que tú indiques.
Si lo rellenas, solo se usará ese prefijo y se dejarán de probar los dosmirrors públicos de arriba; déjalo vacío para que «Automático» decida. El descargador lo antepone a la dirección real.
Los archivos grandes se descargan por fragmentos en paralelo. 8 hilos ya llenan la mayoría de las conexiones domésticas; con una red estable puedes probar 16.
Fuente de actualización de Gitee (opcional)
El repositorio es público y la lista de versiones de Gitee se puede leer sin identificarse, así que puedes dejarlo vacío y seguir usando Gitee. Solo necesitas el token si Gitee está limitado (403/429) o quieres leer una rama privada: gitee.com → Ajustes → Token personal, marca solo «projects»; se usa únicamente para leer la lista de versiones, no se sube nada.
Chequeo local · configuración automática
Revisa este equipo: si la virtualización de la CPU está activada, si Windows tiene la plataforma de hipervisor, qué tarjeta gráfica y memoria tiene, y si la RAM y la versión del sistema son suficientes. Lo que se puede cambiar automáticamente (memoria / núcleos / calidad / backend de renderizado) se escribe directamente en los ajustes, y el resultado se guarda como un perfil de controlador; lo que requiere administrador tiene un botón; lo que solo se puede cambiar en la BIOS se te indicará paso a paso.
Controladores · parches de compatibilidad
Algunas máquinas necesitan cambiar los parámetros de arranque (GLES antiguo, aceleración desactivada, un controlador que falla al renderizar por hardware). Un controlador es un JSON que declara «con qué máquinas coincide» + «qué parámetros cambiar al coincidir». Puedes escribirlo, importarlo y compartirlo. El controlador solo modifica los elementos de arranque incluidos en la lista blanca,No ejecuta ningún código；si no coincide, no se aplica.

Entorno
ApkBuddyStart solo ejecuta su propio entorno: adb, emulador e imagen del sistema los descarga y gestiona él mismo, no detecta ni se hace cargo de ningún emulador instalado (MuMu / LDPlayer / BlueStacks / WSA no se usarán). Así, cambiar de equipo o que otros tengan emuladores instalados no afecta a este programa.
ApkBuddyStart la asigna automáticamente (emulator-5554; si hay conflicto, va aumentando), no hace falta rellenarla.
Solo hay una imagen genérica de Android 14; funciona con aplicaciones x86 y ARM. La primera vez que aparezca una app ARM se descargará automáticamente, sin cambiar nada a mano. Este interruptor solo sirve para compatibilidad con configuraciones antiguas.
